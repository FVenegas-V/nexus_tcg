## Descripción

Implementar el sistema de polling inteligente en Flutter que consulte el backend cada 30 segundos para verificar notificaciones nuevas. El servicio debe ser eficiente, optimizado para batería y configurable según el estado de la aplicación.

**Objetivo:** Crear un servicio Flutter que proporcione notificaciones casi en tiempo real usando polling, manteniendo la experiencia de usuario fluida sin afectar performance ni batería.

**Resultado esperado:** Servicio de notificaciones funcionando que detecta nuevas notificaciones automáticamente y actualiza la UI con badges y contadores.

## Detalles Técnicos y Notas de Implementación

### NotificationService Principal
```dart
class NotificationService {
  static final NotificationService _instance = NotificationService._internal();
  factory NotificationService() => _instance;
  NotificationService._internal();

  Timer? _pollingTimer;
  bool _isPolling = false;
  int _currentInterval = 30; // segundos
  DateTime? _lastCheck;

  // Iniciar polling cuando app está activa
  void startPolling() {
    if (_isPolling) return;
    
    _isPolling = true;
    _pollingTimer = Timer.periodic(
      Duration(seconds: _currentInterval),
      _checkForNotifications,
    );
  }

  // Parar polling cuando app va a background
  void stopPolling() {
    _pollingTimer?.cancel();
    _isPolling = false;
  }

  Future<void> _checkForNotifications(Timer timer) async {
    try {
      final response = await ApiService.get('/api/notifications/unread/');
      final count = response.data['count'];
      
      if (count > 0) {
        _notifyNewNotifications(response.data['latest']);
      }
      
      _lastCheck = DateTime.now();
    } catch (e) {
      _handlePollingError(e);
    }
  }
}
```

### Integración con Lifecycle de App
```dart
class _MyAppState extends State<MyApp> with WidgetsBindingObserver {
  @override
  void initState() {
    super.initState();
    WidgetsBinding.instance.addObserver(this);
    NotificationService().startPolling();
  }

  @override
  void didChangeAppLifecycleState(AppLifecycleState state) {
    switch (state) {
      case AppLifecycleState.resumed:
        NotificationService().startPolling();
        break;
      case AppLifecycleState.paused:
      case AppLifecycleState.inactive:
        NotificationService().stopPolling();
        break;
    }
  }
}
```

## Comentarios y Discusión

**Estrategia de Batería:** El polling solo ocurre cuando la app está activa. Al ir a background, el Timer se cancela automáticamente. Esto es más eficiente que mantener conexiones WebSocket abiertas.

**Configuración Adaptativa:** El intervalo puede ajustarse dinámicamente. Por ejemplo, reducir frecuencia a 60s si no hay actividad nueva por 5 minutos, o aumentar a 15s si hay alta actividad.

**Migración Futura:** Esta implementación facilita migrar a push notifications posteriormente, ya que el NotificationProvider puede recibir notificaciones de cualquier fuente (polling, push, etc.).
