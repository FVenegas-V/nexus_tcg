## Descripción

Implementar el sistema completo de comentarios para posts, incluyendo creación, listado, edición y eliminación de comentarios. Los comentarios deben soportar threading (respuestas a comentarios), validaciones robustas y permisos granulares.

El sistema debe facilitar conversaciones dinámicas en posts, con capacidades de moderación y ordenamiento inteligente para fomentar la interacción constructiva en las comunidades TCG.

---

## Criterios de Aceptación

- [ ] **API POST /api/posts/{id}/comments/** - Crear comentario en post específico
- [ ] **API GET /api/posts/{id}/comments/** - Listar comentarios de un post con paginación
- [ ] **API GET /api/comments/{id}/** - Obtener detalle de comentario específico
- [ ] **API PUT/PATCH /api/comments/{id}/** - Actualizar comentario (solo autor)
- [ ] **API DELETE /api/comments/{id}/** - Eliminar comentario (soft delete)
- [ ] **API POST /api/comments/{id}/reply/** - Responder a comentario específico (threading)
- [ ] **Ordenamiento inteligente**: por fecha, popularidad, relevancia
- [ ] **Paginación eficiente** con carga incremental
- [ ] **Validación de contenido**: longitud, formato, spam detection
- [ ] **Permisos granulares**: membership verification, moderation capabilities
- [ ] **Threading system**: respuestas anidadas hasta 3 niveles de profundidad
- [ ] **Tests completos** para todos los endpoints y casos edge

```python
class Comment(models.Model):
    # Campos existentes...
    parent = models.ForeignKey(
        'self', 
        null=True, 
        blank=True, 
        on_delete=models.CASCADE,
        related_name='replies'
    )
    thread_level = models.PositiveIntegerField(default=0)
    thread_path = models.CharField(max_length=500, blank=True)
    
    def save(self, *args, **kwargs):
        if self.parent:
            self.thread_level = self.parent.thread_level + 1
            self.thread_path = f"{self.parent.thread_path}/{self.parent.id}"
        super().save(*args, **kwargs)
```

## Comentarios y Discusión

### Threading Strategy
- **Máximo 3 niveles**: Evitar threading infinito que complique UX
- **Thread path**: String para ordenamiento eficiente tipo "1/23/456"
- **Lazy loading**: Cargar replies bajo demanda para performance
- **Collapse**: UI debe permitir colapsar threads largos

### Moderación de Comentarios
- **Edit window**: 15 minutos para editar después de crear
- **Soft delete**: Mantener "Comentario eliminado" para preservar threading
- **Auto-moderation**: Detectar spam, links maliciosos, lenguaje ofensivo
- **Community rules**: Aplicar reglas específicas por comunidad

### Performance Considerations
- **Pagination**: Comments paginados + replies lazy loaded
- **Caching**: Cache de comment counts en Redis
- **Database**: Índices compuestos en (post_id, thread_path, created_at)
- **Prefetch**: author, user reactions, reply counts

### Notificaciones (Preparación)
Preparar hooks para notificar:
- Al autor del post cuando recibe comentario
- Al autor del comentario cuando recibe respuesta
- A mencionados en comentarios (@username)
- A moderadores cuando hay reportes
