## Descripción

Implementar Firebase Cloud Messaging (FCM) como extensión del sistema de notificaciones actual para demostrar notificaciones push reales que funcionen aunque la aplicación esté cerrada. Esta implementación está diseñada específicamente para demostración en emuladores Android y como prueba de concepto para evolución futura a producción.

**Contexto:** El sistema actual usa polling cada 30 segundos que funciona excelentemente cuando la app está activa, pero no puede enviar notificaciones cuando la app está cerrada. FCM complementará esta funcionalidad.

## ✅ Análisis de Compatibilidad con Sistema Polling

### **NO HAY CONFLICTOS** - Arquitectura Complementaria

**Polling actual funciona cuando:**
- App está activa/en foreground (cada 30s)
- Usuario navega por la app
- Actualizaciones en tiempo real del badge

**FCM funcionará cuando:**
- App está cerrada/terminated
- App está en background minimizada
- Sistema está dormido/dispositivo bloqueado

### Integración Perfecta con AppLifecycleState

```dart
// NotificationService ya maneja esto correctamente:
case AppLifecycleState.resumed:
  // ✅ Polling activo + FCM foreground handlers
  resumePolling();
  
case AppLifecycleState.paused:
case AppLifecycleState.detached:
  // ✅ Polling pausado + FCM background activo
  pausePolling();
```

**Resultado:** Sistema híbrido robusto que cubre TODOS los escenarios.

## Detalles Técnicos

### Arquitectura Híbrida (Polling + FCM)

```
Evento (nuevo post, comentario, etc.)
    ↓
Django Signal
    ↓
┌─────────────────────┬─────────────────────┐
│   Notification      │    FCM Service      │
│   (Base de datos)   │    (Push real)      │
└─────────────────────┴─────────────────────┘
    ↓                           ↓
Polling Service          Firebase Cloud
(App ACTIVA)             (App CERRADA)
    ↓                           ↓
Badge updates            Push notifications
Real-time UI             System notifications
```

### Backend - FCM Service + Integración con Signals Existentes

```python
# notifications/fcm_service.py
from pyfcm import FCMNotification
from django.conf import settings

class FCMService:
    def __init__(self):
        self.fcm = FCMNotification(api_key=settings.FIREBASE_SERVER_KEY)
    
    def send_notification(self, token, title, body, data=None):
        """Envía notificación FCM a un dispositivo específico"""
        result = self.fcm.notify_single_device(
            registration_id=token,
            message_title=title,
            message_body=body,
            data_message=data
        )
        return result
```

### Frontend - FCM Integration con NotificationService Existente

```dart
// lib/core/services/fcm_service.dart
class FCMService {
  static final FirebaseMessaging _messaging = FirebaseMessaging.instance;
  
  static Future<void> initialize() async {
    // Solicitar permisos
    await _messaging.requestPermission();
    
    // Obtener token para hardcodear en backend
    String? token = await _messaging.getToken();
    print('🔥 FCM Token para backend: $token');
    
    // Configurar handlers SIN interferir con polling
    FirebaseMessaging.onMessage.listen(_handleForegroundMessage);
    FirebaseMessaging.onBackgroundMessage(_handleBackgroundMessage);
  }
  
  static void _handleForegroundMessage(RemoteMessage message) {
    // ✅ Cuando app está activa: solo log (polling ya maneja UI)
    print('📱 FCM foreground: ${message.notification?.title}');
    // NO actualizar UI aquí - polling lo hace en tiempo real
  }
  
  static Future<void> _handleBackgroundMessage(RemoteMessage message) async {
    // ✅ Cuando app está cerrada: mostrar notificación sistema
    print('🔔 FCM background: ${message.notification?.title}');
    // FCM automáticamente muestra la notificación del sistema
  }
}
```

```dart
// lib/core/providers/notification_provider.dart - MODIFICAR
class NotificationProvider extends ChangeNotifier with WidgetsBindingObserver {
  
  void initialize(String authToken) {
    // ✅ EXISTENTE: Inicializar polling
    _notificationService.setAuthToken(authToken);
    _notificationService.startPolling();
    
    // 🆕 NUEVO: Inicializar FCM sin interferir
    FCMService.initialize(); // Funcionará en paralelo
    
    _isInitialized = true;
  }
  
  @override
  void didChangeAppLifecycleState(AppLifecycleState state) {
    // ✅ EXISTENTE: Manejo de polling (sin cambios)
    _notificationService.onAppStateChanged(state);
    
    // 🆕 NUEVO: FCM funciona automáticamente en background
    // No necesita manejo especial del lifecycle
  }
}
```

## 🛡️ Estrategia Anti-Conflictos

### Principios de Diseño
1. **FCM NO toca el estado del NotificationService**
2. **Polling sigue siendo la fuente de verdad para UI**
3. **FCM solo complementa para app cerrada**
4. **Feature flag para fácil disable**

### Separación de Responsabilidades

```
POLLING (Sistema actual - SIN CAMBIOS):
✅ Actualiza badge en tiempo real
✅ Actualiza lista de notificaciones  
✅ Maneja preferencias de usuario
✅ Gestiona estado de leído/no leído
✅ Funciona cuando app está activa

FCM (Sistema nuevo - COMPLEMENTO):
🆕 Envía push cuando app está cerrada
🆕 Muestra notificación del sistema
🆕 Abre app al tocar notificación
🆕 NO modifica estado interno de la app
```

### Testing de Compatibilidad

**Escenarios a validar:**
1. **App activa**: Polling funciona normal, FCM silenciado
2. **App background**: Polling pausado, FCM activo  
3. **App cerrada**: Solo FCM funciona
4. **Volver a app**: Polling resume, sincroniza estado
