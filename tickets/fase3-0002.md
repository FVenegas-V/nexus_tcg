## Descripción

Desarrollar las APIs REST completas para el sistema de posts, incluyendo creación, listado, detalle, actualización y eliminación de publicaciones. Las APIs deben manejar paginación, filtros, permisos granulares y validaciones robustas.

El sistema debe permitir a los usuarios crear posts con texto e imágenes en comunidades donde son miembros, listar posts con filtros inteligentes y gestionar su contenido de manera segura.

### Permisos y Validaciones
```python
class PostPermissions(BasePermission):
    def has_permission(self, request, view):
        # Crear POST: debe ser miembro activo de la comunidad
        # Solo desde página interior de comunidad, no desde feed general
        if request.method == 'POST':
            community_id = view.kwargs.get('community_id')
            return CommunityMembership.objects.filter(
                user=request.user,
                community_id=community_id,
                is_active=True
            ).exists()
        
        # Leer: comunidad pública o es miembro
        return True
        
    def has_object_permission(self, request, view, obj):
        # Editar/Eliminar: solo autor o moderador/admin de la comunidad
        if request.method in ['PUT', 'PATCH', 'DELETE']:
            return (obj.author == request.user or 
                   obj.community.is_moderator(request.user))
```

### Performance Optimizations
- **Prefetch related**: author, community, recent comments
- **Select related**: para reducir queries N+1
- **Cursor pagination**: para feeds largos sin offset penalty
- **Cache de contadores**: Redis para comment_count, reaction_count

## Comentarios y Discusión

### Algoritmo de Feed Personalizado (HOME)
El feed del HOME debe mostrar **solo posts de comunidades suscritas** y priorizar:

1. **Relevancia temporal**: Posts recientes tienen mayor peso (últimas 24-48h)
2. **Interacción social**: Posts con más likes/comentarios suben en ranking  
3. **Afinidad de comunidad**: Comunidades donde el usuario es más activo
4. **Diversidad**: Mezclar contenido de diferentes comunidades suscritas
5. **Trending score**: Algoritmo que combina engagement rate + recencia

**Flujo de Creación de Posts:**
- Usuario navega **DENTRO** de una comunidad específica
- Botón "Crear Post" solo visible para miembros de la comunidad
- Post se crea en contexto de esa comunidad específica
- Post aparece inmediatamente en el feed de la comunidad
- Post puede aparecer en HOME feed de usuarios suscritos (según algoritmo)

### Manejo de Imágenes
- **Upload directo**: Multipart/form-data para crear posts con imágenes
- **Validación**: Tamaño máximo 5MB por imagen, formatos permitidos
- **Optimización**: Resize automático y compresión antes de storage
- **CDN**: URLs optimizadas para diferentes resoluciones

### Consideraciones de Moderación
- **Soft delete**: Campo `is_active` para moderación sin pérdida de datos
- **Reporting**: Preparar estructura para reportes de contenido (fase futura)
- **Auto-moderation**: Hooks para filtros automáticos de contenido
